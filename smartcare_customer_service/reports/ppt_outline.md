## 第 5 页：知识库构建与 RAG 检索（成员 A）

- 7 个知识库文件：32 条 FAQ、3 款耳机说明、售后政策、物流政策、客服流程
- 文档切分：按标题 + 空行分段，长段落滑动窗口
- TF-IDF 检索：中文单字/二元词/三元词 + 英文数字 token → 余弦相似度
- Top-3 检索 → 拼接 prompt → 带引用来源的回答
- 展示"XX 防水吗"的检索结果与来源截图

## 第 7 页：Agent 路由与情绪兜底（成员 A）

路由表/流程图：

- 订单查询 → `query_order`
- 退换货 → `create_ticket`
- 产品咨询 / 保修 / 闲聊 → RAG 知识库
- 投诉 / 人工 → `transfer_human`（高优先级）
- 低置信度 → 引导补充信息或转人工

情绪识别：检测 angry 关键词 → 道歉共情 → 高优先级转人工  
强调：不是所有问题都交给生成模型，而是按场景选择路径

## 第 9 页：Memory 多轮记忆（成员 B）

- SQLite 三张表：`messages`（历史消息）、`session_state`（会话上下文）、`tickets`（工单）
- 会话状态字段：`last_order_id`、`last_product`、`pending_intent`、`last_issue`、`preferred_action`
- 实例演示：第 1 轮提供订单号 → 第 2 轮说"换一个吧" → 系统沿用上下文创建换货工单
- 优势：不依赖 LLM 记忆能力，用结构化状态保证可靠性

## 第 13 页：实验评估（成员 C）

**20 条测试对话评估：**
- 9 个场景、20 条对话，运行 `python3 run_evaluation.py`
- 意图识别准确率：100.0%
- 工具调用正确率：100.0%
- RAG 引用命中率：100.0%

⚠️ **坦诚解读**（建议答辩时主动说明）：
- 100% = 系统在自建封闭测试集上功能完备，逻辑链路闭合
- 不代表开放场景泛化：规则意图 → 对表达方式敏感，自建测试集 → 天然偏向设计场景
- 真实场景预期：错别字/口语/多意图混合会使准确率显著下降

**RAG Top-K 消融实验：**
- 8 个标注问题，比较 Top-1 / Top-3 / Top-5
- Top-1 命中率：87.5%，Top-3 命中率：100.0%，Top-5 命中率：100.0%
- 选择 Top-3 的理由：比 Top-1 更稳，比 Top-5 更精简

**有 RAG vs 无 RAG：**
- RAG 使每个回答可追溯来源，客服可信度远超模板回答
